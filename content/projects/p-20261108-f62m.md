## 🎯 핵심 요약

K-SECRET · SEOUL 1988 캠페인 브라우저 게임 **Kiki's SECRET**을 Claude Code와 함께 만들어 GitHub Pages로 배포했다. 키키의 유리 피부를 지키는 요정 게임에 실제 제품 12종 실사를 얹고, Top 50 랭킹·국가/이메일 수집·인스타 공유 카드까지 갖췄다. 1차(기획서 + 단일 HTML 게임)에서 배포·링크 미리보기·쿨타임 업데이트까지 3일(2026-11-06 ~ 11-08) 만에 끝냈다. 목적은 셋 — 고객·인플루언서에게 제품을 재미있게 소개하기, 공유 카드와 랭킹으로 바이럴 여지 만들기, 두바이 매장 대형 TV에 설치해 고득점 방문객에게 현장 선물을 주는 새 방문 포인트.

## 💡 핵심 인사이트

- **"이 트러블엔 이 제품"을 게임 메커니즘 자체로 각인시켰다** — 2차 요청(시딩 크리에이터·구매 고려 고객 대상)에서 나온 방향. 피부 고민을 선택하면 요정이 제품을 매치해주는 구조라, 게임을 즐기는 과정이 곧 제품 교육이 된다. 10~20대 여성 취향의 파스텔 밤하늘 톤 + 요정의 속삭임 + 일기 스토리로 톤을 맞췄다.
- **로고 노출은 의식이 아니라 무의식에 남긴다** — 3차에서 브랜드 필름 엔드프레임에서 공식 로고를 직접 추출하고, 강한 노출 + 주변시(주변 시야) 반복 노출을 설계했다. "K-SECRET이 무의식에 남도록"이라는 요청을 구조로 풀었다.
- **실사 제품은 신뢰를 만든다** — 4차에서 회사 구글 드라이브의 공식 썸네일 12종을 누끼 따서 요정에 실제 제품 실사를 붙였다. 일러스트만 쓸 때와 비교해 브랜드 진정성이 확 달라진다.
- **디자인 개선도 감이 아니라 레퍼런스로** — 7차에서 키키 캐릭터가 예쁘지 않다는 피드백을 받았을 때, Dribbble·Behance·Freepik에서 얼굴 규칙을 추출해 재디자인했다. "더 예쁘게" 같은 주관 요청을 검증 가능한 규칙으로 바꾸는 방법.
- **차수별 요청→결과 기록이 팀 소통의 핵심 자산** — 1차부터 업데이트까지 모든 요청과 결과를 WORK_LOG로 남겼더니, 회고와 인수인계(사본 저장소 이관)가 그대로 가능했다.
- **배포 인프라도 게임만큼 중요하다** — 슬랙 동기화 실패가 사이트 배포까지 막던 워크플로를 분리(PR #2)해 "누구나 접속"을 확보했다. 링크 미리보기(og:image 1200×630, 하트 자물쇠 파비콘)로 공유 딸려가는 첫인상까지 설계.

## 🛠️ 적용법 가이드

1. **게임 플레이**: https://ksecret-inc.github.io/ksecret-news/beautysecret/ — 저주를 피해 제품으로 키키의 유리 피부를 지키는 단일 HTML 게임. 인트로 카드뉴스 8장 → 피부 고민 선택 → 플레이 → 피부 매치 추천 → 인스타 공유 카드.
2. **랭킹 백엔드**: 구글 앱스 스크립트로 Top 50 랭킹 백엔드 구성 (현재 점수는 기기에만 저장 — 서버 연결은 남은 일).
3. **배포**: GitHub Pages 단일 HTML. og:url/og:image/twitter:image 메타 태그 + 파비콘 세팅.
4. **사본 저장소**: https://github.com/yeaurpoong-think/kikis-secret — 이력 전체(main 43커밋) 복사본. `docs/kiki/GAME_DESIGN.md`(기획서), `docs/kiki/CHANGELOG.md`(차수별 세부 변경), `docs/kiki/WORK_LOG.md`(작업 기록) 참조.

## 💼 활용 예시

- **시딩 크리에이터 섭외**: 게임 링크 + 인스타 스토리형 인트로 카드뉴스를 소재로 전달. "KIKI의 비밀을 지켜줘!" 미리보기로 클릭을 유도.
- **매장 키오스크(계획)**: 두바이 매장 대형 TV에 상시 설치, 고득점 방문객에게 현장 선물. 키오스크 모드와 선물 확인 코드는 개발 대기.
- **캠페인 회고 템플릿**: 차수별 요청→결과 표 + 머지된 PR 목록 구조는 다른 캠페인에도 그대로 재사용 가능.

## ⚠️ 주의사항

- 랭킹 점수가 기기에만 저장된다 — 서버 연결 전까지 랭킹은 기기별로 따로 놀음.
- 매장 공용 기기 설치 시 개인정보 처리(국가·이메일 수집)와 경품 운영 규칙 정리가 선행되어야 함.
- 사본 저장소(kikis-secret)는 Actions를 꺼둔 상태 — 원본의 10분 주기 슬랙 동기화 워크플로가 토큰 없이 실패만 반복하기 때문. 시크릿(슬랙 토큰 등)은 사본으로 옮기지 않았다.
- 원본 Ksecret-inc/ksecret-news는 읽기 전용으로만 — 인수인계 시 이력 복사만 하고 원본 무변경 원칙.
