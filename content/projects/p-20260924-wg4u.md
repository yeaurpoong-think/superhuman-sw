## 🎁 이걸 하면 얻는 것
지금까지 "AI로 하루 관리하기"라고 하면 ChatGPT 창 하나 열어놓고 필요할 때마다 질문 던지는 정도였을 것이다. 이 콘텐츠가 보여주는 건 그보다 한 단계 위 — **음성으로 말만 하면(또는 버튼 하나만 누르면) 알아서 "간단한 답변/AI 요약/실제 코딩 작업" 셋 중 뭐가 필요한지 스스로 판단해서 처리하고, 결과를 옵시디언 볼트에 markdown으로 쌓아 나중에 검색 가능하게 만드는 개인용 AI 운영체제** 청사진이다. 다만 이 게시물 자체는 정확한 설치 저장소를 숨긴 광고이므로, 이 카드는 "그대로 설치하는 법"이 아니라 **"이 구조를 이해하고 비슷하게 직접 구성해보기 위한 설계도"**로 읽어야 한다.

## 🎯 핵심 요약
"The JARVIS OS 2.0"은 **Claude Code/Codex + Obsidian(메모리) + 로컬 음성인식(Whisper)/음성합성(Kokoro) + 자체 분류기 "Jev" + 대시보드(Cockpit·HUD)** 다섯 부품을 조합한 개인용 AI 에이전트 시스템 컨셉이다. 핵심은 **Jev라는 저비용 분류기가 모든 요청을 3단계 티어(즉답/경량모델/실제 작업)로 먼저 분류**해서, 굳이 무거운 모델을 매번 부르지 않고 비용을 아낀다는 설계(원문 주장: "$0.042/백만 입력 토큰, 출력은 무료"). 실제 설치용 저장소("Agentic OS V2")는 댓글로 "JARVIS"를 남겨야 DM으로 받는 구조라, 정확한 GitHub 링크는 공개 화면에 없다 — GitHub 검색으로도 매칭되는 공식 저장소를 찾지 못했다.

## 💡 핵심 인사이트
- **"5 Parts"로 시스템을 명확히 분해했다** — ①Claude Code/Codex(엔진, "실제 작업을 하는 놈") ②Obsidian vault(기억, "모든 결과가 markdown으로 남는다") ③Whisper+Kokoro(귀+입, "음성이 내 컴퓨터를 벗어나지 않는다") ④Jev(분류기, "NEW" 배지 — 각 요청을 올바른 티어로 분류) ⑤Cockpit+HUD(얼굴, "같은 시스템을 보는 두 가지 화면"). 이렇게 역할을 명확히 나눈 구조는 개인 AI 워크플로우를 설계할 때 그대로 참고할 수 있는 틀이다.
- **비용 절감 로직이 구체적 숫자로 제시된다** — "Jev 없이: 메인 모델이 매 요청을 라우팅하는 데 ~$1" vs "Jev 있이: 분류기가 라우팅하는 데 ~$1 미만"(원문 표현 그대로, 정확한 절대값은 인용 안 됨). "Jev는 답을 쓰지 않는다. 정해진 목록에서 하나를 고를 뿐이다"는 설계 원칙 — 저렴한 분류 모델로 라우팅만 시키고, 실제 작업은 필요할 때만 비싼 모델(Claude Code/Codex)로 넘긴다는 것이 요지다.
- **3단계 티어 분류 기준이 명시되어 있다** — Tier 1: 규칙+저장된 데이터로 즉답(예: "내 오늘 우선순위가 뭐야?"), Tier 2: 소형 빠른 모델(예: "오늘 AI 뉴스 요약해줘"), Tier 3: 진짜 작업 — Claude Code/Codex 터미널을 연다. 이 구분 자체가 "모든 요청에 최고급 모델을 쓸 필요 없다"는 비용 최적화 사고방식을 보여준다.
- **"파일이 곧 기억"이라는 원칙** — "vault에 없으면 일어나지 않은 일이다"라는 문구와 함께, 별도 데이터베이스 없이 옵시디언 폴더 구조(inbox/projects/content/wiki)로만 상태를 관리한다. `/harvest`라는 커맨드로 "끝난 프로젝트를 위키 문서로 바꾼다"는 것도 흥미로운 디테일 — 프로젝트 완료 시 자동으로 지식베이스화하는 습관을 시스템에 내장한 것이다.
- **음성 단축키까지 구체적으로 공개됐다** — `Ctrl+Alt+J`로 어느 앱에서든 호출, 말하고 잠깐 멈추면 로컬 Whisper가 받아쓰고, Kokoro가 음성으로 답한다는 흐름. "오디오는 절대 내 컴퓨터를 벗어나지 않는다"는 프라이버시 강조점도 명시적이다.
- **핵심 설치 명령은 딱 한 줄만 공개됐고, 그 한 줄이 가리키는 저장소는 숨겨져 있다** — Step 4 슬라이드에 실제로 보이는 프롬프트는 "Clone the Agentic OS V2 repo into ~/agentic-os and set it up for me."(Claude Code/Codex에 붙여넣으라는 지시)이지만, 정작 "Agentic OS V2 repo"가 어느 GitHub 주소인지는 공개되지 않았다. 계정 캡션의 "Comment 'JARVIS' to get the repo + install prompt"가 이 갭을 메우는 지점 — 정보를 의도적으로 댓글 유도 뒤에 숨긴 구조다.

## 🛠️ 따라 하는 법 (단계별 가이드)

> ⚠️ **먼저 알아야 할 것**: 이 게시물이 가리키는 정확한 GitHub 저장소("Agentic OS V2")는 화면에 공개되지 않았고, 댓글로 "JARVIS"를 남겨야 발신자가 개별 DM으로 보내주는 구조다. 아래는 **원문이 공개한 개념·명령·구조를 그대로 옮긴 것**이며, 실제로 통째로 설치할 수 있는 완성형 가이드는 아니다 — "이런 구조를 스스로 만들어보고 싶다면 무엇이 필요한지" 참고 설계도로 활용할 것.

### STEP 1. 필요한 부품 5개를 먼저 인지한다
1. **Claude Code 또는 Codex** — 실제 코딩/작업을 수행하는 AI 에이전트(둘 중 아무거나, 원문은 "언제든 바꿀 수 있다"고 명시)
2. **Obsidian** — 무료 마크다운 노트 앱(공식 사이트 obsidian.md에서 설치). 모든 결과 리포트가 이 안에 markdown 파일로 쌓인다
3. **Whisper** — 오픈소스 음성인식(로컬 실행, OpenAI가 공개한 모델)
4. **Kokoro** — 오픈소스 텍스트→음성(TTS) 모델(로컬 실행)
5. **Jev(분류기) + 대시보드(Cockpit/HUD)** — 원문이 직접 만든 커스텀 컴포넌트로, 공개 저장소 없이는 그대로 재현 불가능한 부분

### STEP 2. 옵시디언 볼트 폴더 구조를 미리 만들어둔다
1. Obsidian에서 새 볼트(vault)를 하나 만든다
2. 그 안에 폴더 4개를 만든다: `inbox/`(모든 걸 일단 여기로 캡처), `projects/`(진행 중인 작업), `content/`(완성해서 내보낸 것), `wiki/`(배운 것 정리)
3. **확인 지점**: 옵시디언 왼쪽 파일 탐색기에 이 4개 폴더가 보이면 준비 완료

### STEP 3. Claude Code/Codex에 "이 볼트를 기억 저장소로 써라"라고 알려준다
1. 터미널에서 Claude Code 또는 Codex를 실행한다 (각 공식 설치 가이드 참고)
2. 프로젝트 설정 파일(예: `AGENTS.md`나 `CLAUDE.md`)에 "작업 결과를 STEP 2에서 만든 옵시디언 볼트 경로에 markdown으로 저장하라"는 지시를 적어둔다
3. **확인 지점**: 이후 Claude Code에 작업을 시키면 볼트 폴더 안에 새 markdown 파일이 생기는지 확인한다

### STEP 4. (원문 공개 프롬프트) 저장소 클론 시도
1. Claude Code 또는 Codex를 연다
2. 원문이 공개한 프롬프트를 그대로 붙여넣는다: `Clone the Agentic OS V2 repo into ~/agentic-os and set it up for me.`
3. **확인 지점 — 여기서 막힌다**: 이 프롬프트가 가리키는 "Agentic OS V2" 저장소 주소를 AI가 알지 못하므로, 실제로는 실행되지 않는다. 원문 게시자만 정확한 저장소 위치를 알고 있고, 댓글 "JARVIS"에 대한 DM으로만 공유하는 구조다.
4. 대신 스스로 구성하려면: 위 STEP 1~3에서 모은 부품(Claude Code/Codex + Obsidian + Whisper + Kokoro)을 각각 공식 문서대로 설치하고, "Jev 분류기" 역할은 직접 작은 스크립트(예: 저비용 LLM API 호출로 "이 요청은 즉답/요약/작업 중 뭐냐"만 판단하게 하는 라우터)로 대체 구현해볼 수 있다.

## 💼 활용 예시
- **서고(superhuman-sw) 운영 자체에 적용**: "요청을 먼저 저비용 모델로 분류한 뒤 필요한 것만 무거운 작업으로 넘긴다"는 Jev의 핵심 아이디어는, 서고 카드 제작 파이프라인에서 "이건 인사이트 소비형인가 실행 튜토리얼형인가"를 먼저 가볍게 판단하고 그다음 본격 리서치로 들어가는 흐름과 개념적으로 비슷하다.
- **SR바이오텍 업무 자동화 아이디어**: 옵시디언 폴더 구조(inbox/projects/content/wiki)를 회사 인사 업무 노트 정리에 그대로 차용할 수 있다 — "일단 다 inbox에 던지고, 끝난 프로젝트는 wiki로 정리"하는 습관화가 핵심 아이디어다.
- **개인 AI 비서 구축 참고 설계도**: 저장소 없이도 "음성 명령 → 3단계 티어 분류 → Claude Code 실행 → 옵시디언 기록"이라는 전체 파이프라인 구조 자체는 참고해서 직접 훨씬 단순한 버전(예: 티어 분류 없이 그냥 Claude Code + Obsidian 연동만)부터 만들어볼 수 있다.

## ⚠️ 주의사항
- **이 게시물은 리드제너레이션(광고) 콘텐츠다** — 캡션에 "Comment 'JARVIS' to get the repo + install prompt"라고 명시되어 있어, 실제 GitHub 저장소 주소와 완전한 설치 스크립트는 화면에 공개되지 않았다. GitHub 검색(`Agentic OS V2`, `jarvis os obsidian whisper kokoro` 등 키워드)으로도 매칭되는 공식 저장소를 찾지 못했다 — 존재하지 않거나 비공개 상태로 추정된다.
- **"$0.042/백만 토큰" 등 비용 수치는 원문 주장 그대로이며 재검증하지 않았다** — 실제 어떤 모델을 "Jev" 분류기로 쓰는지 명시되지 않아 이 비용이 어느 모델 기준인지 알 수 없다.
- **"21개의 스킬"(Browse all skills 21) 같은 구체적 숫자도 이 특정 게시자의 개인 설정값이지, 공식 스펙이 아니다** — 저장소가 공개되지 않았으므로 실제 스킬 목록 21개가 무엇인지 확인 불가능.
- **Whisper·Kokoro·Obsidian·Claude Code/Codex는 전부 실재하는 도구다** — 이 넷은 각각 독립적으로 설치·검증 가능하며, 카드에 언급된 조합 자체가 허구는 아니다. 다만 이들을 "Jev"라는 분류기로 엮는 접착 코드(glue code)가 이 게시물의 핵심 자산이고, 그 부분만 비공개다.
