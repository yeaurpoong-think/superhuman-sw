## 🎯 핵심 요약

한 대의 Hostinger VPS(KVM8) 안에 5개의 독립 Docker 컨테이너를 띄워 SR바이오텍 HR팀 5명에게 각자 격리된 헤르메스 인스턴스를 제공하는 프로젝트의 **AI-to-AI 인수인계 문서**. 1번(석원님) 인스턴스는 세팅·텔레그램 연결까지 완료됐고, 나머지 4명(ARA/ARI/LSH/LDJ)은 세팅 대기 상태로 문서가 작성됐다. 핵심은 "왜 이렇게 결정했는지"의 배경과, 겪었던 13가지 트러블슈팅 케이스가 그대로 기록되어 있다는 점.

## 💡 핵심 인사이트

- **1 VPS + 5 컨테이너 구조를 선택한 이유는 순수 비용**: 5개 개별 VPS는 월 $45, 1 VPS + 5 컨테이너는 월 $15~20. Hostinger 공식 지원 방식은 아니지만(첫 컨테이너를 복제해 포트만 바꾸는 방식) 비용 절감 효과가 커서 복잡성 트레이드오프를 감수함.
- **KVM8(8vCPU/32GB/200GB)을 고른 이유**: 팀 성장 여유분 + 성능 여유. 연간 약정 전에 1개월 테스트($50.99)로 먼저 검증.
- **Traefik 리버스 프록시로 서브도메인 라우팅**: 포트번호(`:4860` 등) 직접 접속은 타임아웃 — Traefik이 호스트네임 기반으로만 라우팅하므로 반드시 서브도메인 URL(`hermes-agent-5n8e.srv1708227.hstgr.cloud` 등)로 접속해야 한다.
- **인증/모델 실수가 반복 발생 지점**: OAuth(1번) 선택 시 HTTP 400, Opus 선택 시 과도하게 느림 — 두 실수 모두 "다음 AI/사람"에게 명시적으로 경고해두지 않으면 매 인스턴스 세팅마다 반복된다.

## 🛠️ 적용법 가이드

**서버 정보**: IP `187.77.117.64` / 도메인 `srv1708227.hstgr.cloud` / Ubuntu 24.04.4 LTS

**컨테이너 구조**:
- `/docker/hermes-agent-5n8e/` → User1(석원님, 4860)
- `/docker/hermes-agent-user2~5/` → User2~5(ARA/ARI/LSH/LDJ, 4861~4864)
- `/docker/traefik/` → 리버스 프록시(HTTPS 라우팅)

**표준 운영 절차**:
1. `ssh root@187.77.117.64` (Windows CMD, 우클릭 붙여넣기)
2. `docker exec -it hermes-agent-5n8e-hermes-agent-1 /bin/bash` (인스턴스별로 `5n8e`를 `user2~5`로 교체)
3. `HERMES_ALLOW_ROOT_GATEWAY=1 hermes gateway restart`
4. 모델 변경 시: `hermes setup model` → `Use existing credentials` → `claude-sonnet-4-6`

**신규 인스턴스(2~5번) 세팅 15단계**: `hermes setup` → Quick setup → Anthropic → **API key(2번, 반드시)** → 키 붙여넣기(IME OFF) → **claude-sonnet-4-6(반드시)** → TTS/터미널 Keep current → Messaging 설정 → Telegram → 봇 토큰·유저ID 입력 → 홈채널 `y` → 게이트웨이 재시작 `y` → `HERMES_ALLOW_ROOT_GATEWAY=1 hermes gateway restart`

**당시 진행 상태 스냅샷 (2026-05-27 기준, 참고용)**:
- ✅ 완료: VPS 구매·프로비저닝, 인스턴스1 배포, 인스턴스 2~5 복제, 포트/방화벽 설정, 인스턴스1 API키·모델·텔레그램봇 연결 및 동작 확인
- ❌ 미완료: 게이트웨이 systemd 백그라운드 서비스 등록, 인스턴스 2~5 전체 세팅, 전원 초기 비밀번호 변경, 연간/월간 플랜 결정

## 💼 활용 예시

- 새 AI 세션(또는 새 담당자)이 이 프로젝트를 이어받을 때, 배경 설명 없이 바로 "왜 API키인지, 왜 Sonnet인지, 왜 이 구조인지"를 파악하고 실수 재현 없이 이어서 진행 가능
- 팀원 인스턴스 2~5 세팅을 진행할 때 15단계 체크리스트를 그대로 따라가면 됨
- 게이트웨이가 다운됐을 때 13개 트러블슈팅 케이스(P1~P13)에서 증상으로 바로 원인·해결책 조회

## ⚠️ 주의사항

- **사용자는 비개발자** — 터미널 지식을 전제하지 말고, 한 번에 하나씩 지시하며 스크린샷으로 확인받을 것
- **Windows PC 붙여넣기는 우클릭**, Ctrl+V 아님 — 헷갈리면 IME OFF 여부부터 확인
- 반복 실패 시 사용자가 좌절하기 쉬우므로, 같은 방법 재시도보다 원인 진단 후 다른 접근을 시도할 것
- 게이트웨이는 CMD 창을 닫으면 죽는 foreground 프로세스 — systemd 서비스 등록(`hermes gateway install`)이 안 되어 있다면 서버 재시작 시 수동 재기동 필요
- 이 문서의 "PENDING" 항목(인스턴스 2~5 세팅, systemd 등록 등)은 2026-05-27 기준 스냅샷이므로 실제 최신 진행 상태는 별도 확인 필요
