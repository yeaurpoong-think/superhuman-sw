> 📝 출처: YLZ MEDIA 블로그 칼럼 「글 한 편이 5개 채널에 알아서 올라갑니다」(2026-10-06). 채널별 변환 프롬프트 5종은 원문 그대로 옮겼어요. 하단의 유료 클래스·구축 대행 안내는 넣지 않았어요.

## 📚 원본 링크
- [글 한 편이 5개 채널에 알아서 올라갑니다 — YLZ MEDIA](https://www.ylzstudio.com/blog/one-post-five-channels)

## 🎁 이걸 하면 얻는 것
- **Before**: 같은 글을 블로그, 네이버, 링크드인, 스레드에 하나씩 고쳐 올리느라 편당 20~30분 × 5채널, 주 2시간 넘게 쓴다. 결국 채널 하나가 밀리면 방치된다.
- **After**: **칼럼 1편만 쓰고**, 프롬프트 4개를 돌려 채널별 버전을 받는다. 매일 10분 복붙(또는 자동 발행 + 승인 1번)으로 5채널이 굴러간다.
- 덤으로 같은 글이 카드뉴스 → 릴스로 이어져서 **한 편이 최종 7~8곳**에 도달한다.

## 🎯 핵심 요약
콘텐츠를 채널마다 새로 만들지 말고 **원문 1편 → AI 채널별 재작성 → 발행 큐 → 사람 승인 1번 → 자동 발행** 구조로 바꾸라는 글이다. 핵심은 복붙이 아니라 **채널마다 문법(말투·구조·길이)을 프롬프트로 고정**하는 것. 인스타그램은 공식 API로 캐러셀 게시·첫 댓글 CTA·댓글 DM 발송까지 자동이 되고, 틱톡은 API 심사 전이라 1분 수동 업로드로 남긴다.

## 💡 핵심 인사이트
- **같은 메시지, 다른 문법**: 블로그는 표·인용구가 들어간 완성형, 링크드인은 번호 리스트 + "~입니다"체, 네이버는 한 문장마다 줄 바꿈 + 인용구 3개 뼈대, 페이스북은 3줄 요약 + 링크, 스레드는 첫 줄 훅 + 단문. 이 규칙을 "알아서 잘"이 아니라 **프롬프트에 명시**해야 톤이 안 무너진다.
- **채널 간 중복은 불이익이 아니다**: 플랫폼은 자기 안의 콘텐츠만 본다. 문제는 같은 채널 안의 반복, 그리고 형식 변환 없는 통복사다.
- **"전부 자동"이 아니라 "되는 곳만 자동"**: 인스타는 API로 끝까지 자동, 틱톡은 1분 수동 루틴. 안 되는 걸 억지로 자동화하지 않는 게 설계 원칙이다.
- **사람은 판단, 시스템은 발행**: "자동화는 발행을 맡기는 것이지 판단을 맡기는 게 아니다." 승인 루프 하나만 남긴다.
- **가장 흔한 실패는 처음부터 5개**: 본진(블로그) + 내 고객이 있는 채널 1개로 시작해서, 루틴이 잡히면 하나씩 늘린다.
- **AI 티는 규칙과 내 숫자로 지운다**: 말투 규칙 고정 + 원문에 내 사례·숫자 넣기 + 승인 단계에서 사람이 한 번 거르기.

## 🛠️ 따라 하는 법 (단계별 가이드)

**준비물**
- ChatGPT 또는 Claude (무료 버전도 가능)
- 메모장(또는 노션 페이지 하나)
- 운영할 채널 2개: 본진 블로그 + 고객이 있는 채널 1개

**STEP 1. 칼럼 1편을 쓴다 (주 1회, 30~60분)**
1. 그 주의 주제로 초고를 쓴다. 내 사례와 숫자를 반드시 넣는다.
2. 아래 **칼럼 다듬기 프롬프트**에 초고를 붙여넣는다.
   ```
   아래 초고를 사이트에 올릴 칼럼으로 다듬어줘.

   규칙:
   - 구조: 도입(문제 제기) → 본문(소제목 3~5개) → 핵심 요약 → 마무리
   - 같은 축의 항목이 3개 이상이면 표로 정리한다
   - 제목은 검색 키워드를 포함해 3안 제안
   - 과장 금지: 수치·사실은 원문에 있는 것만 쓴다

   원문:
   [여기에 초고 붙여넣기]
   ```
   → 소제목이 나뉘고 제목 후보 3개가 붙은 완성형 칼럼이 나온다. 이게 블로그(본진) 원문이다.

**STEP 2. 채널별 버전을 받는다 (쓴 직후, 10분)**
완성된 칼럼을 아래 프롬프트에 각각 붙여넣고, 결과를 메모장에 채널별로 저장한다.

네이버 블로그용
```
아래 글을 네이버 블로그 글로 다시 써줘.

규칙:
- 한 문장이 끝날 때마다 줄을 바꾼다 (긴 문단 금지)
- 글의 뼈대는 인용구 3개: 맨 앞(훅) · 중간(핵심 요약) · 맨 끝(행동 유도)
- 인용구로 쓸 문장은 [인용구] 표시로 구분해서 보여줘
- 소제목 3~5개로 섹션을 나눈다
- 제목은 검색할 법한 키워드를 넣어 2안 제안

원문:
[여기에 칼럼 붙여넣기]
```
→ 결과에 `[인용구]` 표시가 3군데 보이면 정상이다. 네이버 글쓰기에서 그 문장만 인용구 블록으로 바꾼다.

링크드인용
```
아래 글을 링크드인 게시물로 다시 써줘.

규칙:
- 전부 "~입니다" 체. 반말·음슴체 금지
- 구조: 훅 1~2줄 → 번호 리스트(항목 = 소제목 한 줄 + 설명 1~2줄) → 마무리 질문 1줄
- 전체 1,000자 이내
- 이모지·해시태그 없음
- 원문에 없는 사실을 추가하지 않는다

원문:
[여기에 칼럼 붙여넣기]
```

페이스북용
```
아래 글을 페이스북 게시물로 다시 써줘.

규칙:
- 핵심만 3~5문장으로 요약하고, 첫 문장은 결론부터
- 마지막 줄에 "전체 내용은 댓글의 링크에서 보실 수 있습니다" 추가
- 존댓말 유지, 해시태그 없음

원문:
[여기에 칼럼 붙여넣기]
```

스레드용
```
아래 글을 스레드 게시물로 다시 써줘.

규칙:
- 첫 줄이 전부다: 스크롤을 멈출 훅 한 줄로 시작
- 전체 500자 이내, 문장은 짧게 끊는다
- "~입니다" 체를 유지하되 대화하듯 쓴다
- 해시태그·이모지 없음
- 마지막 줄은 독자에게 던지는 질문

원문:
[여기에 칼럼 붙여넣기]
```

**STEP 3. 요일을 고정해서 하루 한 채널씩 올린다 (매일 10분)**
- 예: 월 링크드인 · 화 네이버 · 수 페이스북 · 목 스레드
  → 한 주가 지나면 칼럼 1편이 4~5개 채널에 깔려 있다.

**STEP 4. 귀찮아지면 그때 자동화한다**
원문이 제안하는 순서(세팅 6단계)는 이렇다.

| 단계 | 할 일 | 포인트 |
|---|---|---|
| 1 · 채널 연결 | 메타 개발자 계정, 링크드인·네이버 앱 등록으로 API 키 발급 | 처음 한 번, 가장 지루하지만 중요 |
| 2 · 변환 규칙 | 위 프롬프트를 AI 지시로 고정 | 채널마다 문법을 명시 |
| 3 · 발행 큐 | 변환된 글을 날짜별로 쌓고 스케줄러가 매일 발행 | 하루 1편이 알고리즘에 유리 |
| 4 · 승인 루프 | 발행 전 사람이 한 번 확인 | 판단은 사람이 |
| 5 · 이미지 채널 | 인스타 공식 API로 캐러셀 게시·첫 댓글·댓글 DM | 틱톡은 수동 1분 |
| 6 · 추적 루프 | 채널별 반응을 모아 다음 주제에 반영 | 많이 읽힌 주제가 다음 재료 |

## 💼 활용 예시
- **숏폼 트렌드 리포트 (개인 프로젝트)**: 주간 리포트 원문 1편 → 네이버 블로그 버전(줄 바꿈 + 인용구) + 스레드 훅 + 인스타 캐러셀 → 숏폼 댓글 링크. 지금 구상 중인 "노션 원본 → 네이버 배포" 흐름에 이 변환 규칙을 그대로 붙이면 된다.
- **헤르메스와 함께 쓰기**: 헤르메스가 원문을 쓰고 채널별 변환까지 해서 넘기면, 석원님은 승인과 붙여넣기만 한다. 한국어는 `korean-humanizer`로 한 번 더 다듬는다.
- **케이시크릿 팀 공지·채용 브랜딩**: JD나 컬처 글 1편을 링크드인(전문가 톤)·인스타(캐러셀)·블로그로 나눠 배포할 때도 같은 규칙을 쓸 수 있다.

## ⚠️ 주의사항
- **출처 성격**: 콘텐츠 대행사(YLZ MEDIA)의 칼럼이다. 본문 끝에 유료 원데이 클래스와 구축 대행 안내가 붙어 있다. 프롬프트와 구조는 무료로 공개된 부분만 옮겼다.
- **수치**: "주 2시간 이상 → 칼럼 1시간 + 승인 1분"은 작성자 운영 경험 기준(원문 인용, 재검증 못 함).
- **네이버 자동 발행은 안 된다**: 네이버는 블로그 글쓰기 API를 종료했다. 원문 표에 "네이버 앱 등록"이 있지만, 네이버 블로그는 현실적으로 **복붙 수동 발행**이다(비공식 자동화는 계정 제재 위험).
- **인스타 자동 게시**: 비즈니스·크리에이터 계정과 메타 개발자 앱 설정이 필요하다. 댓글 DM 자동 발송도 메타 정책(24시간 응답 창 등)을 지켜야 한다.
- 처음부터 5채널을 다 돌리지 않는다. 본진 + 1개로 시작.
