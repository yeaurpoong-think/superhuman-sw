## 요약

혼자 콘텐츠를 만들 때 하던 "조사 → 첫 문장 → 대본 → 디자인 → 발행 → 분석"을 Claude Code 서브에이전트 7개로 나눠 맡기는 방법을 정리한 노션 가이드. 사람을 뽑는 대신 `.md` 파일 7개를 만들어 각각을 "직원"으로 쓰는 방식이며, 설치에 약 30분이 걸린다고 소개함.

핵심 원칙: 만드는 사람(편집장)은 사라지지 않는다 — 아이디어를 고르고 완성본을 승인하고 올릴지 정하는 건 여전히 본인 몫. 글의 질은 본인 안목·말투에서 나오고, 이 구조는 "손이 가는 일"만 덜어주는 장치.

## 1. 조직도 — 역할 분담

- **나(편집장)** → 관리 담당에게 지시
- **관리 담당**: 나머지 6명을 순서대로 호출
- **조사 담당**: 주제·유행을 찾는다
- **첫 문장 담당**: 손을 멈추게 하는 첫 줄을 쓴다
- **대본 담당**: 40초 대본으로 늘린다
- **디자인 담당**: 자막·썸네일·표지를 만든다
- **분석 담당**: 숫자를 읽고 규칙을 찾는다
- **발행 담당**: 예약을 걸고 올린다

흐름: 조사 → 첫 문장 → 대본 → 디자인 → (승인) → 발행 → 분석 → (배운 것을 들고) 다시 조사로 순환.

**승인 지점은 딱 2곳**: ① 아이디어가 나왔을 때(어느 주제로 갈지 고른다) ② 완성본이 나왔을 때(올릴지 말지 정한다)

## 2. 폴더 구조

```
content-team/
├── CLAUDE.md                  ← 회사 규칙. 분야·말투·CTA를 여기 적는다
├── .claude/
│   └── agents/                ← 직원 일곱 명이 사는 곳
│       ├── research.md
│       ├── hook-writer.md
│       ├── script-writer.md
│       ├── designer.md
│       ├── analyst.md
│       ├── manager.md
│       └── publisher.md
├── brand/
│   ├── voice.md               ← 내 말투. 예전에 잘된 캡션 3~5개를 그대로 붙여 넣는다
│   └── swipe-file.md          ← 먹혔던 첫 문장·구성을 모아 두는 곳
├── pipeline/
│   ├── ideas.md               ← 아이디어 받은 편지함
│   ├── calendar.md            ← 언제 무엇을 올릴지
│   └── scripts/               ← 완성된 대본
└── results/
    └── performance.md         ← 올린 글과 그 숫자
```

`.claude/agents/` 안에 파일만 넣으면 Claude Code가 자동으로 서브에이전트("직원")로 인식 — 별도 등록 불필요.

## 3. 직원 7명 — 지시문(프롬프트) 요약

1. **조사 담당(research.md)** — 도구: 웹 검색, 유튜브 자막, swipe-file.md / 출력: 순위 매긴 아이디어 5~10개 → `pipeline/ideas.md`. "숫자·조회수를 지어내지 마라" 원칙 명시
2. **첫 문장 담당(hook-writer.md)** — 아이디어 1개 → 첫 3초용 첫 줄 10개(내 말투로), 각 줄이 건드리는 지점(궁금증/반대/손해) 표시
3. **대본 담당(script-writer.md)** — 첫 줄 → 40초(약 250자) 대본. 짜임: 첫 줄→알맹이→솔직한 한계→CTA
4. **디자인 담당(designer.md)** — 자막 7개(각 3~5단어), 고정 댓글 훅 문구, 표지 한 줄, 촬영 화면 목록
5. **분석 담당(analyst.md)** — 입력: 조회수·좋아요·댓글·저장 숫자 / 출력: 잘된 것 3·끊을 것 3·다음 주 바꿀 것 1개. "짐작하지 말고 준 숫자만 근거로" 명시
6. **관리 담당(manager.md)** — 조사→첫문장→대본→디자인→분석→발행 순서로 호출, 승인 지점 2곳에서 반드시 정지
7. **발행 담당(publisher.md)** — 캡션+해시태그+예약시각 묶어 최종본 작성. "가자"라고 할 때까지 절대 자동 발행 금지

## 4. CLAUDE.md(회사 규칙) 템플릿

```
이건 내 AI 콘텐츠 팀이다. 편집장은 나다.
내 분야: [분야]. 내 독자: [누구]. 내 말투: [설명]. 내 CTA 방식: [예 — 「댓글에 ○○ 남기면 DM으로 보냄」].
직원은 .claude/agents/에 산다 — 조사·첫 문장·대본·디자인·분석·관리·발행.
기본 순서: 관리 → 조사가 아이디어 → 내가 고름 → 첫 문장 → 내가 고름 → 대본 → 디자인 →
내가 완성본 승인 → 발행이 예약 → 내가 마지막 「가자」.
모든 직원 공통 규칙: ①내 말투로(뻔한 말투 금지) ②숫자·성과 지어내지 않기 ③경쟁자는 구성만 참고, 내용 도용 금지
④대본 전·발행 전 반드시 승인받기 ⑤분석은 실제로 준 숫자만 사용
```

## 5. 붙이면 좋은 도구(MCP)

- 웹 검색·페이지 읽기 → 조사 담당
- 파일 읽기/쓰기(기본 내장) → 전체
- 디자인 도구(Canva 등) → 디자인 담당
- 예약 도구(Buffer·Later 등) → 발행 담당
- 노션·스프레드시트 → 분석 담당

처음엔 웹 검색 + 파일 읽기/쓰기만으로 충분, 나머지는 흐름이 자리잡은 후 추가 권장.

## 6. 30분 설치 순서

1. **0~5분**: Claude Code 설치, `content-team` 폴더 생성 후 `claude` 실행, CLAUDE.md에 회사 규칙 붙여넣기(분야·독자·말투·CTA 질문에 답변)
2. **5~15분**: `.claude/agents/` 폴더 생성 + 파일 7개. 직접 안 만들어도 "이 안내문 보고 직원 일곱 명 파일 만들어 줘"라고 하면 Claude가 뼈대를 잡아줌
3. **15~22분**: `brand/voice.md`에 예전에 잘된 캡션 3~5개 붙여넣기(말투를 가르치는 유일한 재료), `brand/swipe-file.md`에 좋아하는 첫 문장 몇 개
4. **22~30분**: "관리 담당, [주제]로 릴스 하나 만들어"로 한 바퀴 테스트 — 승인 지점마다 승인하면 끝까지 진행

이후 운영: "관리 담당, 이번 주 릴스 3개 만들어" → 아이디어 승인 → 완성본 승인 → 발행. 주마다 숫자를 분석 담당에게 넘기면 다음 주 방향이 나옴.

## 참고 사항

- 원문에 실제 실행 광고 링크("AI자동화 비용 88% 절약")가 삽입돼 있음 — 별도 유료 서비스 홍보성 콘텐츠일 가능성, 본 요약에서는 제외
- Claude Code(터미널 기반) 전제 — 이전에 등록한 "YC 대표 gstack"(클로드 데스크탑 Code 탭) 가이드와는 실행 환경이 다름, 둘 다 서브에이전트/역할분리 철학은 유사
- BeauT오빠 콘텐츠 자동화나 서고 라이브러리 운영에 그대로 응용 가능한 구조 — 실제 적용 시 이 구조를 참고할 만함
- 실제 설치·검증은 아직 하지 않음(원문 리서치 단계)
