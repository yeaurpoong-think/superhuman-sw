## 🎯 핵심 요약

헤르메스는 질문-답변 챗봇이 아니라 **서버 위에서 24시간 돌아가며 스스로 학습·개선하는 자동화 에이전트**다. 팀원 개인용으로 붙이려면 VPS(추천: Hostinger 원클릭 설치) 위에 설치하고, 모델은 Claude Sonnet 계열, 메신저는 디스코드나 텔레그램으로 연결하면 된다. 세팅 자체보다 "반복 업무 하나를 한 달 맡겨보는 것"이 핵심 성공 조건이다.

## 💡 핵심 인사이트

- **자가진화**: 문제를 해결하면 그 방법을 스킬로 자동 저장 → 다음번엔 같은 문제를 더 잘 처리한다. OpenClaw처럼 수동으로 스킬을 관리할 필요가 없다.
- **가볍고 안정적**: 오래 켜둬도 메모리 누수·연결 끊김이 적어 24시간 서버 운영에 적합하다.
- **통합 메모리**: 모닝 브리핑, 마케팅, 코드베이스 작업이 전부 같은 컨텍스트를 공유해 매번 처음부터 설명할 필요가 없다.
- **추천 역할 분담**: 소프트웨어 개발은 Claude Code, 리서치·자동화·일상 업무는 헤르메스로 나누는 것이 실전에서 가장 효율적이었다.
- **모델 선택이 체감 성능을 좌우**: 저성능 모델을 쓰면 "헤르메스 자체가 별로다"라고 오해하기 쉽다. 성능-비용 균형이 맞는 모델(Sonnet급)을 쓸 것.

## 🛠️ 적용법 가이드

**설치 환경**: 집 PC(무료지만 보안·상시가동 부담), 전용 PC 구매(초기비용 부담), **VPS(권장)** 중 VPS가 최선 — 월 $9 수준으로 24시간 자동 운영되고 메인 PC에 보안 위험이 없다.

**추천 VPS**: Hostinger — 헤르메스 원클릭 Docker 설치를 지원해 터미널 명령어 없이 클릭 몇 번으로 끝난다. 플랜은 KVM2로 충분.

**설치 순서 (원클릭 경로)**:
1. Hostinger 가입 → KVM2 플랜 선택 → 쿠폰코드로 10% 할인
2. VPS 탭 → 새 VPS 생성 → Docker 애플리케이션 검색창에 `hermes` 입력 → 설치
3. Quick Setup 진입

**초기 세팅 핵심**:
- 모델: Claude 계열(Sonnet) 권장. API 키 발급 후 커스텀 선택 시 Base URL + API 키 + 모델명(`gpt-4o` 등) 입력
- 메신저(디스코드 예시): Discord Developer Portal에서 New Application → Bot 탭 Reset Token(토큰은 한 번만 표시되므로 즉시 저장) → OAuth2에서 `bot` + `applications.commands` 스코프 체크 → 생성된 링크로 서버에 봇 초대 → 헤르메스 세팅 화면에 토큰·유저ID·서버(채널) ID 입력 → Gateway 실행

**자주 쓰는 슬래시 명령어**: `/skill`(테마 변경), `/insight`(세션 분석), `/steal`(작업 중 방향 수정 개입), `/bytheway`(기억에 안 남는 질문)

## 💼 활용 예시

1. **크론 스케줄링**: "매일 아침 7시에 AI 뉴스 3개 요약해줘" 처럼 자연어로 정기 자동화 지시
2. **모닝 브리핑**: 이메일·캘린더·관심 토픽 연결 시 매일 아침 자동 요약 — 2주 정도 지나면 브리핑 품질이 눈에 띄게 좋아진다(누구에게 답장하는지, 어떤 회의를 준비하는지 학습하기 때문)
3. **웹 모니터링**: 내장 스텔스 브라우저로 경쟁사 가격 변경 감지, SNS 게시물 분석, 앱스토어 저평점 리뷰 수집 등 구조화된 데이터 추출
4. **SNS 포스팅 초안**: 최신 정보 기반 3줄 요약 포스팅 초안을 매일 자동 생성 → 마음에 드는 것만 확장해서 발행
5. **서비스 오류 대응**: Sentry 등과 연결하면 오류 로그 감지 → 수정안 제안/직접 수정 → 아침에 처리 결과 리포트
6. **A/B 테스트 자동화**: 이메일 오픈율·전환율 목표를 정의하면 스스로 실험을 설계하고 이전 결과 기반으로 다음 변경을 예측

## ⚠️ 주의사항

- 첫날 결과가 완벽하지 않은 게 정상 — 헤르메스는 쓸수록 강해지므로 최소 한 달은 평가를 유보할 것
- 나의 반복 업무를 먼저 목록화하고, 충분한 정보(SNS 계정, 관심 분야, 업무 패턴)를 제공할수록 정확도가 올라간다
- 세팅 자체를 계속 만지작거리는 "최적화 함정"에 빠지지 말고, 반복 작업 하나를 실제로 한 달 돌려서 가치를 검증하는 데 집중할 것
