# 프로젝트 파일 계약

이 문서는 **에이전트(클로드 코드, 헤르메스)와 사람이 함께 지키는 형식 명세**다.
앱 코드를 읽지 말고 이 문서만 보고 파일을 만들면 된다.

프로젝트 1건 = `content/projects/<id>.md` 파일 1개. 이 레포가 곧 데이터베이스다.

## 파일 형식

```markdown
---
id: instagram-hook-teardown
title: 인스타 훅 구조 분해
rank: a0
tags: [instagram, copywriting]
sources:
  - url: https://www.instagram.com/reel/XXXX/
    type: reel
    title: 훅 3초 법칙
post_url: null
researched_at: 2026-09-01T01:00:00Z
executed_at: null
published_at: null
---

여기부터 본문 마크다운.
```

## 필드

| 필드 | 필수 | 설명 |
|---|---|---|
| `id` | ✅ | **파일명(확장자 제외)과 반드시 같아야 한다.** 소문자·숫자·하이픈만. 한 번 정하면 영구히 바꾸지 않는다 — 카드의 주소다 |
| `title` | ✅ | 사람이 읽는 제목. 한글 자유롭게 |
| `rank` | ✅ | 컬럼 안에서의 정렬 키. 새로 만들 때는 `a0`으로 두면 된다. 사이트에서 드래그하면 알아서 다시 매겨진다 |
| `researched_at` | ✅ | 리서치를 끝낸 시각. ISO 8601 UTC (`2026-09-01T01:00:00Z`). 날짜만(`2026-09-01`) 써도 그날 자정으로 읽는다 |
| `tags` | | 문자열 배열. 없으면 생략하거나 `[]` |
| `sources` | | 리서치를 촉발한 원본 목록. `url` 필수, `type`은 `reel`·`carousel`·`article`·`video`·`link` 중 하나(기본 `link`), `title`은 선택 |
| `post_url` | | 발행한 블로그 글 주소. 아직 없으면 `null` |
| `executed_at` | | 실제로 해본 시점. 아직이면 `null` |
| `published_at` | | 콘텐츠를 발행한 시점. 아직이면 `null` |

계약에 없는 키를 추가로 넣어도 지워지지 않는다. 다만 화면에는 나오지 않는다.

## 칸반 컬럼은 저장하지 않는다

컬럼은 **타임스탬프에서 유도**한다. `status` 같은 필드를 만들지 마라. 무시된다.

| 컬럼 | 조건 |
|---|---|
| 리서치 완료 | `executed_at`이 비어 있다 |
| 실행 완료 | `executed_at`이 있고 `published_at`이 비어 있다 |
| 콘텐츠 완료 | `published_at`이 있다 |

그래서 **새 리서치를 올릴 때는 `researched_at`만 채우고 나머지 둘은 `null`로 둔다.** 그러면 '리서치 완료' 칸에 카드가 생긴다.

## 새 프로젝트를 올리는 절차

1. `content/projects/<id>.md` 를 위 형식으로 만든다
2. `npm run validate` 로 형식을 확인한다 (선택이지만 권장 — CI가 어차피 검사한다)
3. `main`에 커밋·푸시한다. 1~2분 뒤 사이트에 반영된다

형식을 어긴 파일이 들어오면 CI가 실패하고, 사이트에는 그 카드가 빨간 '스키마 오류' 카드로 뜬다. 다른 카드는 멀쩡히 보인다.

## 본문에 대한 주의

- **frontmatter에 주석(`#`)을 쓰지 마라.** 사이트에서 편집·저장하면 사라진다
- 각주(`[^1]`), 원시 HTML, 참조형 링크(`[x]: url`)를 쓰면 사이트 편집기가 리치 모드 대신 원문 모드로 연다. 내용이 손상되지는 않는다
- 표·목록·코드블록·인용은 자유롭게 쓴다

실제 예시는 [`_example.md`](./_example.md) 참고.

## 리서치 문서의 본문 구조

인스타 릴스·캐러셀이나 링크에서 뽑아낸 리서치는 아래 구조로 쓴다.
노션에 쌓던 형식을 그대로 옮긴 것이다.

```markdown
## 🎯 핵심 요약
## 💡 핵심 인사이트
## 🛠️ 적용법 가이드
## 💼 활용 예시
## ⚠️ 주의사항
## 📚 원본 링크
```

두 가지 원칙이 형식보다 중요하다.

- **슬라이드 순서대로 나열하지 않는다.** 전체를 합본해 주제 중심으로 다시 쓴다. 두괄식
- **검증하지 못한 주장은 검증한 척하지 않는다.** 원출처를 못 찾았으면 "원문 인용, 재검증 못 함"이라고 본문에 밝힌다

링크에서 내용을 뽑아내는 절차 전체는 [`RESEARCH-PIPELINE.md`](./RESEARCH-PIPELINE.md)에 있다.
