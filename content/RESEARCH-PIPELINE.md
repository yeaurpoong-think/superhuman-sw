# 인스타 링크 → 리서치 문서 변환 로직

클로드·헤르메스가 링크 하나를 받아 `content/projects/` 파일 하나로 만들기까지의 전체 절차.
파일 형식 자체는 [`CONTRACT.md`](./CONTRACT.md)를 따른다.

## 1. 입력 타입 판별

| URL | 종류 | `sources[].type` |
|---|---|---|
| `instagram.com/reel/{id}/` | 릴스(동영상) | `reel` |
| `instagram.com/p/{id}/` | 캐러셀 또는 단일 이미지 | `carousel` |

`img_index=N` 파라미터가 붙어 있어도 **무시하고 1번 슬라이드부터 전체를 훑는다.**
그 값은 공유할 당시 보던 화면일 뿐, 중요한 슬라이드라는 뜻이 아니다.

## 2. 콘텐츠 추출 — 3단계 폴백

인스타는 봇 차단이 심하다. 한 경로만 믿으면 반드시 막힌다.

### 1순위 · instaloader

```python
import instaloader

L = instaloader.Instaloader()
post = instaloader.Post.from_shortcode(L.context, shortcode)
caption = post.caption
for node in post.get_sidecar_nodes():      # 캐러셀이면 슬라이드별 순회
    url = node.video_url if node.is_video else node.display_url
```

- 공개 계정은 로그인 없이 바로 된다. 비공개·연령제한 계정만 `sessionid` 쿠키가 필요하다
- 이미지가 `.heic`로 내려오는 경우가 있다. **비전 모델에 넣기 전에 `ffmpeg`로 jpg 변환은 필수다**

### 2순위 · 브라우저 자동화

instaloader가 막혔을 때. 페이지를 열고 로그인 유도 팝업을 닫은 뒤, 캡션은 접근성 스냅샷 텍스트에서 읽고 슬라이드 이미지는 비전으로 읽는다.
슬라이드가 6장을 넘으면 Next 버튼을 반복해 누르는 것보다 `img_index=N` URL로 직접 접근하는 쪽이 빠르다.

### 3순위 · 사용자에게 요청

레이트리밋이나 세션 문제로 둘 다 막히면, 추측해서 채우지 말고 스크린샷이나 캡션 텍스트를 직접 요청한다.

### 릴스 특화

- 캡션에 핵심이 다 들어 있는 경우가 많다. **캡션을 먼저 확인하고, 부족할 때만 영상을 받는다**
- 프레임 분석이 필요하면 `ffmpeg -vf fps=1`로 뽑되, 총 프레임이 15~20장을 넘지 않게 fps를 조절한다

## 3. 가공 — 여기가 제일 중요하다

### 하지 말 것

- **"슬라이드 1번: ~~, 슬라이드 2번: ~~" 식 순서 나열.** 절대 금지
- 원문을 그대로 옮기는 단순 요약

### 할 것

- 전체 슬라이드와 캡션을 합본한 뒤 **주제 중심으로 완전히 재구성**한다
- **두괄식.** 결론과 핵심 메시지를 맨 앞에, 근거와 배경은 뒤에
- 독자가 원본을 보지 않아도 이해되는 **완결형 문서**로 쓴다

### 본문 표준 구조

```markdown
## 🎯 핵심 요약
결론부터. 3~4문장.

## 💡 핵심 인사이트
왜 중요한지 3~5개.

## 🛠️ 적용법 가이드
단계별 실행법.

## 💼 활용 예시
실무 시나리오 2~3개.

## ⚠️ 주의사항
한계와 리스크.

## 📚 원본 링크
```

## 4. 팩트체크 — 내용을 그대로 믿지 않는다

카드뉴스와 릴스가 말하는 회사명·수치·주장은 원출처를 찾아 대조한다.

- 오픈소스 도구가 나오면 → GitHub API로 stars·license·최근 업데이트를 직접 확인
- 시장 데이터가 나오면 → 원문 매체(TechCrunch 등)를 직접 검색해 대조
- **이름만 나오고 URL이 없는 도구는 주소를 추측해 접속하지 않는다.** 영상 프레임 속 주소창 텍스트를 읽거나, 화면 UI의 고유 문구로 역검색한다
- 검증이 물리적으로 불가능하면 **"원문 인용, 재검증 못 함"이라고 본문에 그대로 밝힌다.** 사실인 것처럼 단정하지 않는다

## 5. 저장

예전에는 노션 API(`POST /v1/pages`)로 저장했다. 이제는 이 레포에 커밋한다.

가공한 마크다운을 파이프로 넘기면 파일이 만들어진다. **frontmatter를 직접 쓰지 마라.**

```bash
cat 가공한-리서치.md | npm run new -- --title "인스타 훅 3초 구조 분해" --url "https://www.instagram.com/reel/XXXX/" --category content
```

`id`·`rank`·`researched_at` 은 명령이 계산하고, 링크 모양을 보고 `reel`/`carousel` 도 알아서 붙는다.
카드는 '리서치 완료' 칸 맨 위에 생긴다.

분류는 `agent` · `automation` · `content` · `business` · `market` · `marketing` 중 하나다.
**애매하면 아예 빼라.** 억지로 끼워 맞추면 나중에 걸러 볼 때 방해만 된다.

그다음 `npm run validate` 로 확인하고 `main`에 커밋·푸시한다.

섹션 구조(요약·인사이트·가이드·주의사항)는 노션에 쓰던 것을 그대로 유지한다.

## 6. 실전에서 걸리는 것들

- **`.heic` 이미지는 비전 모델이 못 읽는다.** 항상 jpg로 변환하고 처리한다
- 캐러셀이 11장을 넘으면 서브에이전트로 나눠 병렬 처리하고, **8장 이하는 순차 처리가 오히려 안정적이다**
- 슬라이드 이미지 파일 자체(원작자가 디자인한 그래픽)를 그대로 다시 호스팅하는 것은 정보 추출과는 다른 문제다. **텍스트와 수치는 자유롭게 재구성해도 되지만, 이미지 파일을 통째로 복제해 올리는 것은 저작권 문제가 있다.** 올리기 전에 판단한다
